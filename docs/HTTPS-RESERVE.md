# Резервный HTTPS-порт

В **Админка → Настройки**, сразу под **2FA — двухфакторная защита**, находится блок **Резервный HTTPS-порт для VPS**. Включите галочку **8443**, нажмите **Применить порт** и дождитесь статуса. Обычно применение занимает до 15 секунд. Ссылки на сайт и админку появятся в этом же блоке.

Адрес: `https://ваш-домен:8443`. Основной порт 443 сохраняется. В браузере резервный адрес всегда содержит `:8443`.

## Что нужно на VPS

- Установить актуальную версию через обычное обновление проекта.
- Сначала настроить HTTPS с действующим сертификатом для основного домена.
- Освободить TCP 8443, если он занят другим сервисом. Служба не останавливает чужие процессы.
- Разрешить TCP 8443 в используемом firewall и в сетевых правилах провайдера. Проект не меняет эти правила автоматически.

Локальная проверка подтверждает ответ сайта через HTTPS на VPS. Она не доказывает доступность порта из каждой внешней сети — откройте опубликованную ссылку с нужного устройства.

## Если после открытия пропадает порт

Обновление исправляет передачу исходного `Host` через Nginx: порт `:8443` сохраняется при формировании перенаправлений. Вход `/admin` теперь возвращает временное относительное перенаправление на `/admin/`, без перехода на 443. Установка и обновление применяют это и к существующим конфигурациям проекта, сохраняя сертификаты и другие сайты.

Если браузер уже запомнил прежнее постоянное перенаправление, откройте **`https://ваш-домен:8443/admin/login`** напрямую. Для ярлыка iOS используйте адрес с `/admin/` и завершающим слешем. После переходов проверьте, что адрес по-прежнему содержит `:8443`.

Этот фикс устраняет потерю порта в HTTP-переходах. Если соединение обрывается до ответа HTTP, нужна отдельная проверка TLS и сетевого пути; смена порта не гарантирует устранения сетевой фильтрации.

## Смена домена

Настройка хранит только флаг включения порта. Домен и сертификат берутся из действующего HTTPS-блока проекта в Nginx, без привязки к прежнему адресу. После смены DNS, переноса Nginx на новый домен и установки сертификата резерв использует новый домен автоматически. Изменение поля «Домен сайта» в веб-админке само по себе не выпускает сертификат и не переносит серверный виртуальный хост.

Если при смене домена создаётся новый HTTP-конфиг без TLS, резерв не будет включён до завершения настройки HTTPS. Обновите также домен и URL платежей в настройках приложения.

## Платежи и push

Для использования 8443 как адреса донатов установите:

- URL возврата в настройках сайта: `https://ваш-домен:8443/payment/success`.
- HTTP-уведомления в **личном кабинете ЮKassa**: `https://ваш-домен:8443/webhooks/yookassa`; отразите этот же адрес в поле Webhook URL на сайте. Сохранение поля на сайте не меняет настройки кабинета ЮKassa.

Ярлык iOS и push-подписки привязаны к источнику с портом; подключите их заново, открыв админку на 8443. После настройки проведите тестовый платёж.

## Применение и безопасность

Flask сохраняет только значение `HTTPS_RESERVE_ENABLED=0/1` в базе. Веб-процесс не получает sudo или доступ к записи конфигурации Nginx. Отдельная root-служба проверяет этот единственный флаг раз в 10 секунд. Само чтение SQLite выполняется с правами пользователя `zks95`, чтобы не создавать root-файлы WAL/SHM. Служба выполняет установленную root-копию помощника из `/usr/local/libexec/new-donat-zks95/`, а не изменяемый веб-пользователем файл из каталога приложения.

Меняется только блок существующего сайта в `/etc/nginx/sites-available/new-donat-zks95.conf`. Перед изменением создаётся резервная копия в `/var/backups/new-donat-zks95/https-reserve/`. После `nginx -t`, плавного reload и локальной HTTPS-проверки публикуется статус. При ошибке применения возвращается прежний конфиг. Другие сайты, сертификаты и занятые порты не удаляются.

Ручная настройка 8443, выполненная до установки этой функции, автоматически подхватывается. Перезагрузка и обновление сохраняют включение. Отключение закроет доступ через резервный адрес.

## SSH-команды

```bash
sudo systemctl status new-donat-zks95-https-reserve.timer --no-pager
sudo systemctl status new-donat-zks95-https-reserve.service --no-pager
sudo journalctl -u new-donat-zks95-https-reserve.service -n 50 --no-pager
sudo systemctl start new-donat-zks95-https-reserve.service
sudo cat /var/lib/new-donat-zks95-network/status.json
sudo nginx -t
```

Для oneshot-службы `inactive (dead)` между запусками — нормальное состояние; таймер должен быть активен, а последний запуск завершён успешно. Во время установки/обновления служба пропускает цикл из-за общей блокировки и повторяет проверку после завершения обслуживания.
